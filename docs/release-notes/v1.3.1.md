## The picture no longer flickers on an application that rewrites its title

RetroArch keeps the frame rate in its window title, and it rewrites that title
while the game runs. The source named the captured window by its title, so to
the source it looked like a different window every time it checked, and it
pointed both child captures at it again. Each of those pointings tore the
capture down and built it back: the picture blinked, and a game capture hook
that had just succeeded was thrown away before anything was drawn with it. One
session on RetroArch did this 605 times.

A window is now identified by its handle, which does not change while the window
lives. The title can say what it likes.

Browsers do the same thing on a smaller scale, writing the page name into the
title on every tab switch, so a tracked browser gains from this too.

A capture that comes up empty is now pointed at the window again, a few seconds
apart, as long as the window is alive and on screen. Window capture takes
nothing but an exact match of the title it was given, so a title rewritten in
the moment between reading it and using it used to leave the source showing
nothing until you switched applications and came back.

The log is quieter for the same reason as the fix: a retitled window is no
longer reported as a new target.

## Картинка перестала моргать на приложениях, которые переписывают заголовок

RetroArch держит частоту кадров в заголовке окна и переписывает его по ходу
игры. Источник опознавал захваченное окно по заголовку, поэтому на каждой
проверке видел будто бы новое окно и перенаводил на него оба дочерних захвата.
Каждое такое перенаведение сносило захват и поднимало заново: картинка моргала,
а удавшийся хук захвата игры выбрасывался, не успев ничего показать. За один
сеанс RetroArch это повторилось 605 раз.

Теперь окно опознаётся по его дескриптору, а он при жизни окна не меняется.
В заголовке может быть что угодно.

Браузеры делают то же самое помельче: вписывают имя страницы в заголовок на
каждом переключении вкладки. Отслеживаемый браузер тоже выигрывает от правки.

Захват, поднявшийся пустым, теперь перенаводится на окно ещё раз, с паузой в
несколько секунд, пока окно живо и на экране. Захват окна принимает только
точное совпадение заголовка, который ему выдали, поэтому заголовок, переписанный
в промежутке между чтением и применением, оставлял источник пустым до тех пор,
пока вы не переключитесь на другое приложение и обратно.

Лог стал тише по той же причине, что и правка: переименованное окно больше не
считается новой целью.
