## Automatic mode stands by the backend it picked

A rule set to **Automatic** chose between game capture and window capture on
every frame, and whichever came up last took the picture over. Game capture can
get its hook into an ordinary application minutes after it starts trying, and
what it hands over then need not be anything you want on screen. Blender went
black that way: window capture had been showing it for minutes, then you opened
a project, the hook got in while it loaded, and the canvas went dark and stayed
dark.

The source now picks a backend when the application becomes the target and
stands by it. A backend that stops delivering frames gives the picture up at
once, so nothing sticks to a dead capture. For the first ten seconds the choice
can still change: a game needs about that long to be hooked.

If you worked around this by putting a rule on **Window capture**, you can set
it back to **Automatic**.

## Game capture leaves other applications alone

While game capture is aimed at something, its hook knocks at that process every
two seconds for as long as the application is on screen. On Blender that came to
102 attempts in four minutes, and none of them could have succeeded.

The source now aims it only where a rule might use it. A rule on window capture
never knocks at all. In automatic mode the source stands it down once window
capture has held the picture past those ten seconds, since by then it cannot win
the target anyway. Measured on Notepad: four attempts instead of one every two
seconds for as long as the application stays open.

## A closed window no longer costs you the check interval

Close the window being captured and the source notices in the same frame instead
of waiting for the next check. At the maximum interval of five seconds that was
five seconds with nothing on the canvas, and switching to OBS to find out why
made it worse: OBS matches no rule, so the canvas stayed empty until you went
back to the application.

Alt+Tab is unchanged. The last frame stays on screen while the window is alive
and another rule has not claimed the capture.

## Removing an application no longer throws the page to its foot

Click **Remove selected** and the settings page jumped down to the poll interval.
Qt moves the keyboard focus off a widget as it is disabled, the page scrolls to
wherever that focus landed, and the remove button goes dead the instant the list
has nothing selected. The focus now goes to the button next to it, and the page
stays where you are looking.

## Автоматический режим стоит за выбранным бэкендом

Правило в режиме **«Автоматически»** выбирало между захватом игры и захватом
окна каждый кадр, и картинку забирал тот, кто поднялся последним. Хук захвата
игры садится на обычное приложение через минуты после начала попыток, и отдать
он может что угодно. Blender чернел именно так: захват окна показывал его
минутами, потом вы открывали проект, за время загрузки хук пролезал внутрь, и
холст темнел насовсем.

Теперь источник выбирает бэкенд в момент, когда приложение становится целью, и
дальше за ним стоит. Бэкенд, переставший отдавать кадры, освобождает картинку
сразу, так что застрять на мёртвом захвате нельзя. Первые десять секунд выбор
ещё может перемениться: примерно столько нужно игре, чтобы зацепиться.

Если вы обошли это, поставив правило на **«Захват окна»**, можно вернуть
**«Автоматически»**.

## Захват игры не трогает чужие приложения

Пока захват игры наведён на цель, его хук стучится в этот процесс каждые две
секунды, сколько бы приложение ни было на экране. На Blender это 102 попытки за
четыре минуты, и ни одна из них не могла удаться.

Теперь источник наводит его только туда, где он может пригодиться правилу.
Правило с захватом окна не стучится вовсе. В автоматическом режиме источник
снимает его с цели, как только захват окна удержал картинку дольше тех самых
десяти секунд: выиграть цель он уже не может. Замер на Блокноте: четыре попытки
вместо одной каждые две секунды, пока приложение открыто.

## Закрытое окно больше не стоит вам интервала проверки

Закройте захваченное окно, и источник заметит это тем же кадром, а не на
следующей проверке. При максимальном интервале в пять секунд это были пять
секунд пустого холста, а переключение в OBS, чтобы разобраться, положение
только ухудшало: сама OBS ни одному правилу не отвечает, и холст оставался
пустым, пока вы не вернётесь в приложение.

Alt+Tab работает как работал: последний кадр держится на экране, пока окно живо
и захват не забрало другое правило.

## Удаление приложения больше не бросает страницу вниз

Щелчок по кнопке **«Убрать выбранное»** уносил страницу настроек к интервалу
опроса в самом низу. Qt уводит фокус с виджета, который выключают, страница
прокручивается туда, куда фокус попал, а кнопка удаления гаснет сразу, как
только в списке не остаётся выбора. Теперь фокус переходит на соседнюю кнопку,
и страница остаётся там, куда вы смотрите.
